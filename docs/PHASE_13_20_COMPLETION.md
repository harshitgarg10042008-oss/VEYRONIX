## Phase details

### Phase 13 — Frontend integration and evidence workbench

The React/Tailwind operator workbench is integrated under `frontend/`. It presents audit posture, findings, source evidence, framework mapping, remediation preview language, unknown-syntax queue, offline state, and LLM-disabled trust boundaries. The UI contains no live-device action and keeps the deterministic backend as the source of truth.

### Phase 14 — Responsive and accessible operator experience

The dashboard uses an asymmetric desktop workbench with a compact mobile navigation mode, semantic buttons for operator actions, visible status language, keyboard-reachable controls, and a reduced-motion rule. The desktop and mobile layouts preserve the evidence-first flow instead of collapsing into a marketing-only surface.

### Phase 15 — Offline demo orchestration surface

The frontend exposes local audit context, isolated-network status, input-hash metadata, local-run feedback, and preview-only remediation copy. The backend continues to perform the actual parsing and evaluation; the interface does not imply that a device connection exists.

### Phase 16 — Review queue and unknown-syntax operator loop

Unknown syntax is surfaced as a bounded review queue with pending state and vendor context. The existing learning-loop implementation remains authoritative. The UI communicates the safe sequence: AI suggests, an operator approves, and the control pack learns.

### Phase 17 — Reporting and framework traceability surface

Findings expose control IDs, severity, status, evidence line references, and CIS/NIST mapping language. JSON and Markdown reports are generated by the SDK and CLI rather than by client-side invented data.

### Phase 18 — Safe remediation preview surface

The selected finding includes source evidence and a safe preview action. Remediation remains preview-only in the local demo and is generated by the hardened backend path. No frontend control applies configuration to a device.

### Phase 19 — Governance and extension seams

The repository documents explicit extension seams for future cloud controls, GitOps policy gates, signed control-pack distribution, RBAC, audit-log export, and enterprise tenancy. These are not fake integrations. They require deployment, credentials, and additional contracts beyond the local SIH demonstration.

### Phase 20 — Final local delivery gate

Run the following from a clean checkout:

```text
python -m pytest
python -m compileall -q src tests examples
python -m build
cd frontend && pnpm install --frozen-lockfile && pnpm run check && pnpm run build
PYTHONPATH=src python examples/local_demo.py
```

The GitHub commit is the source-of-truth delivery artifact. The frontend can also be previewed locally with `cd frontend && pnpm dev`.

## Authority and honesty contract

> Normalize locally, evaluate deterministically, show source evidence, let an operator approve a preview, and keep LLM suggestions subordinate to policy code.

VEYRONIX does not claim hosted cloud controls, live GitOps enforcement, or remote device mutation in this local-first delivery. Those capabilities remain future work behind explicit adapter and policy boundaries.
